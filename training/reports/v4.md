# v4 — 배깅(bootstrap-aggregated ridge coefficients)

브랜치: `SmartRouter-v4` (base: `SmartRouter-v3`)

## 무엇을 했나

선형모델이라 여러 부트스트랩 재학습의 계수를 평균내는 게 여러 모델의 예측을
평균내는 것과 수학적으로 동일하다는 점을 이용(`mean(w_b @ x) == mean(w_b) @ x`).
`training/train_router.py`에 `bag_ridge()` 추가: 1,760개 행을 복원추출로
30회(`BAGGING_ROUNDS`) 재표본, 매번 ridge 재적합, 계수를 평균. 표준화
(mean/scale)는 전체 데이터에서 한 번만 계산해 모든 재표본이 같은 단위를
쓰게 함(안 그러면 계수 평균이 무의미해짐). 실행 시점 비용 증가 없음
(계수 하나로 미리 합쳐지므로).

## 실측 결과 (Dev 880, 공식 self-check)

| | v3 | v4(배깅) |
|---|---:|---:|
| final | 0.672670 | **0.671477 (-0.00119)** |
| fast | 0.627841 | 0.627841 (동일) |
| balanced | 0.690625 | 0.691761 (+0.00114) |
| premium | 0.714489 | 0.709375 (**-0.00511**) |

premium이 유일하게 유의미하게 나빠짐: axk1-think 선택이 62개→42개로 줄고,
risk[axk1-think]도 3.00→4.00(더 엄격)으로 재선택됨 — 배깅한 비용 예측이
axk1-think를 원래보다 더 위험하게(비싸게) 보이도록 만든 것으로 추정.

## 결론

**기대(꼬리오차 완화)와 반대 방향으로 작동함.** 가설: 선형 ridge는 이미
분산이 낮은 모델이라 배깅으로 얻을 게 적고, 30회 재표본이 원본 1,760개
행의 실제 분포를 크게 못 바꿔서 계수가 원래 fit과 별 차이가 없거나,
안전계수 재탐색 과정과 얽혀서 우연히 더 보수적인 조합을 고르게 만든
것으로 보임. 원인을 더 깊이 파려면 배깅 전/후 axk1-think의 log-cost
예측값 자체를 문항별로 비교해봐야 하는데, 우선순위상 보류.

**처리**: main 브랜치에 병합하지 않음. `SmartRouter-v5`는 v3에서 다시
분기해서 진행 (v4의 회귀를 안 들고 감).
