# v5 — 특성별 차등 정규화 (손수 특징 vs 해시 슬롯)

브랜치: `SmartRouter-v5` (base: `SmartRouter-v3`)

## 무엇을 했나

손수 고른 10개 특징(신뢰도 높음)과 256개 해시 슬롯(단어 충돌로 노이즈
많음)이 지금까지 같은 `alpha`로 규제되고 있었다. `fit_ridge`가 스칼라
대신 `(columns,)` 배열도 받게 확장(`np.diag(alpha_vec)`), 해시 슬롯에만
추가 배수(`HASH_ALPHA_MULTIPLIER_GRID=[1,2,4,8,16]`)를 곱해 OOF MSE로
탐색.

## 결과: OOF MSE는 개선, 실제 Dev 점수는 악화

- score: `hash_multiplier=4`에서 MSE 0.16774→0.16675로 개선
- cost: `hash_multiplier=1`(=no-op)이 최선 — 추가 규제가 오히려 해로움

| | v3 | v5 |
|---|---:|---:|
| final | 0.672670 | **0.670852 (-0.00182)** |
| fast | 0.627841 | 0.626705 |
| balanced | 0.690625 | 0.691193 |
| premium | 0.714489 | 0.709375 |

## 결론

**OOF MSE 개선이 실제 배분 결과 개선으로 안 이어짐.** score 예측이
정밀해져도 그게 λ-이분탐색·안전계수 재보정과 얽히면서 다른 방향으로
움직인 것으로 보임 — v4(배깅)에서도 같은 패턴이 나왔다(사전 지표는
좋아 보이는데 최종 파이프라인 결과는 나빠짐). 두 번 연속으로 "점 추정
모델 자체를 정교화"하는 접근이 역효과였다는 게 이번 회차의 진짜
결론일 수 있음 — 이 방향(전처리, 마커 단어 확장 등)은 재검토 필요.
