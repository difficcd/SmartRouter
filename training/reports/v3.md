# v3 — 모델별 경성(hard) 비용 상한

브랜치: `SmartRouter-v3` (base: `SmartRouter-v2`)

## 배경

IDEA.md에 있던 미답변 질문: "hash_regex처럼 예측이 완전히 틀리는 경우에도 대응할
수 있게 수식을 짜는 건 어떤가? 각 모델별 고정 최대값을 지정해준 다음, 그 경계
내부에서 ML적 할당해주면?" — `risk_multiplier`는 "비용 예측이 맞다는 전제 하에"
비싼 모델을 억제하는 연성(soft) 장치라, 예측 자체가 틀리면(hash_regex가 실제로
당한 사고) 억제 강도를 아무리 세게 잡아도 못 막는다. 예측 정확도와 무관하게
항상 성립하는 경성(hard) 상한을 추가한다.

## 변경

`_team_select_models`(heuristic.py)/`allocate_vectorized`(calibrate_safety.py)의
λ-이분탐색에 두 번째 제약을 추가: `high_cap_ratio`(기본 1.0=제약 없음, 기존과
완전히 동일)로 axk1-think가 등급 cap의 이 비율을 넘지 못하게 한다. 페널티가
커질수록 axk1-think 선택도 단조감소하므로(가장 비싸서 제일 먼저 배제됨),
기존 이분탐색 구조를 안 바꾸고 위반 조건에 `OR`로 조건 하나만 추가하면 됨.

`training/calibrate_safety.py`: `(risk_mid, risk_high, safety_ratio)`를 이미
찾은 뒤, `HIGH_CAP_GRID=[1.0, 0.90, ..., 0.50]`에서 **점수 손해(0.001 이내)
없이 조일 수 있는 가장 엄격한 값**을 등급별로 별도 탐색해서 추가.

## 실측 결과 (Dev 880, 공식 self-check)

| | v2 | v3 |
|---|---:|---:|
| final | 0.672670 | **0.672670 (동일)** |
| fast | 0.627841 | 0.627841 (`high_cap_ratio=1.00`, 제약 안 걸림) |
| balanced | 0.690625 | 0.690625 (`high_cap_ratio=1.00`, 제약 안 걸림) |
| premium | 0.714489 | 0.714489 (`high_cap_ratio=0.70`, **제약 걸렸는데 점수 그대로**) |

**Dev 점수 변화 없이 premium에 axk1-think 70% 경성 상한을 얻었다.** fast/
balanced는 애초에 axk1-think 비중이 낮아 상한이 안 걸림(예측 정확도 문제와
무관하게 항상 여유). premium은 오늘 Dev에서는 상한이 안 걸리지만
(`model_counts.axk1-think=62`가 여전히 선택됨, 총 비용이 우연히 상한 아래),
**예측이 지금보다 더 틀리는 상황(비공개 평가셋)에서 axk1-think 쪽으로
쏠리는 걸 구조적으로 막아준다** — hash_regex가 실제로 당한 사고
(Premium 예측 3.985/한도 4.0 → 실제 4.2 → 0점)를 재현할 수 없게 만드는
장치.

## 리스크·미확인 사항

- `SCORE_TOLERANCE=0.001`, `HIGH_CAP_GRID` 후보 값은 이번에 새로 도입한
  제 임의 선택 — 사용자 확인 전 잠정치.
- 실제로 예측이 얼마나 틀려야 이 상한이 발동하는지(발동 문턱)는 별도로
  스트레스 테스트 안 해봄 — IDEA.md에 이미 있던 "합성 최악 시나리오" 아이디어로
  검증하면 좋을 후보.
