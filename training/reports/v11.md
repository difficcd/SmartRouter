# v11 — 비용 모델을 역할별로 분리 (랭킹용 / 예산용)

브랜치: `SmartRouter-v11` (base: `main` @ v10)

## 배경

v10에서 cost alpha를 실제(exp) 스케일 기준으로 고르자 premium은 크게 올랐는데
(+0.008) fast는 오히려 떨어졌다. 원인을 실측으로 확인:

**비용 예측은 서로 다른 두 가지 일을 하고 있었고, 각각 최적 정규화가 반대다.**

| 역할 | 무엇을 요구하나 | 최적 alpha |
|---|---|---:|
| **랭킹** — 어느 문항을 승격할지 (EV 비교의 `gain/cost`) | 문항 간 판별력, 상대 비율 | **낮음** |
| **예산** — 이 배치가 총 얼마일지 (`cap`, 합계) | 절대 수준 정확도 | **높음** |

Train 실측(fast greedy, 완벽 비용회계 가정 -> 랭킹 품질만 변수):

| alpha | fast 점수 | 승격 수 |
|---:|---:|---:|
| 300 | 0.6423 | 960 |
| 1000 | 0.6382 | 835 |
| 10000 | 0.6294 | 683 |
| 100000 | **0.6213** | 527 |

랭킹은 alpha가 낮을수록 좋고, 실제스케일 오차는 alpha가 높을수록 좋다.
v10은 후자만 최적화해서 premium을 얻고 fast를 잃었다.

## 변경

같은 log-cost 타깃을 **두 번 학습**한다:

- `log_cost_heads` + `cost_smear` — 예산용. `select_cost_alpha`(실제 스케일 오차)로
  선택 -> alpha=1e5. `cap`과 총합 계산에만 사용.
- `log_cost_rank_heads` + `cost_rank_smear` — 랭킹용. `select_alpha_single`(log MSE
  = 상대오차)로 선택 -> alpha=1000. EV 비교에만 사용.

두 모델 모두 각자의 배치합 보정계수를 갖는다(원시 exp() 수준이 서로 다르므로).
`_team_select_models`/`allocate_vectorized`가 `light_total`도 각각 따로 계산한다.

## 실측 결과 (Dev 880, 공식 self-check)

| | main(v8) | v10 | **v11** |
|---|---:|---:|---:|
| **final** | 0.674205 | 0.675511 | **0.677273 (+0.00176)** |
| fast | 0.627841 | 0.627273 | **0.631250** |
| balanced | 0.692330 | 0.689489 | 0.692330 |
| premium | 0.717898 | **0.725852** | 0.723580 |

**fast가 처음으로 0.6278 고착에서 벗어났다** (ax31 승격 47 -> 99개).
v1부터 v10까지 fast는 어떤 변경에도 0.6273~0.6278에 붙어 있었는데, 랭킹
전용 비용 모델을 주자 움직였다 — 진단에서 예측한 그대로다.

부트스트랩 단계에서도 세 등급 모두 안전계수가 올라갔다(예산 여유를 실제로
더 쓸 수 있게 됨): fast 0.84->0.88, balanced 0.94->0.96, premium 0.80->0.84.

원본 main(0.672500) 대비 누적 **+0.00477**.

## 남은 것

- premium은 v10(0.725852)이 v11(0.723580)보다 근소하게 높다. 예산용 모델은
  동일하므로 랭킹 모델 변경의 부작용으로 보이는데, 등급별로 랭킹 alpha를
  따로 고르면 회수 가능할 수 있다(지금은 세 등급이 같은 랭킹 모델을 공유).
- fast는 여전히 이론 천장(진단 §4의 0.6460, 완벽 비용회계 가정)과 0.015 차이.
